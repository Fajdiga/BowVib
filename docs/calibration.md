# Calibration and measurement verification

Raw counts are never overwritten by calibration. Existing high-g conversion is 0.010417 g/LSB, as specified for the ±320 g setting in the [ST datasheet](https://www.st.com/resource/en/datasheet/lsm6dsv320x.pdf); calibrated XYZ and the chosen calibration object are stored separately in NPZ/CSV/JSON exports.

1. Identify the board/sensors, location and orientation of each module, bow, archer, arrow, draw force, stabilizers and mounting method in the shot metadata. Photograph or draw the local XYZ axes. Confirm all expected sensors are detected.
2. Inspect the mount and cables, then place the sensors on a stable fixture. For the baseline offset command, all present sensors must have the same known gravity vector in their local axes. Otherwise measure each sensor in its own known orientation and combine the independently obtained offsets in the calibration file.
3. Record a stationary reference: set pre-trigger to 10 s, post-trigger to 0 s, automatic threshold to 0. Arm, wait for readiness and trigger. Download it and check quality/window coverage before deleting it.
4. Run `python shot_tool.py calibrate reference.bvr calibration.json --gravity 0 0 1`, substituting the known local gravity vector. The command requires ≥9.9 s of retained stationary data per present sensor and rejects flagged shots. Review `stationary_std_g`: unexpected scatter or mean shifts require inspection and another baseline. No universal acceptable noise threshold is assumed.
5. Repeat in the six known +X/−X/+Y/−Y/+Z/−Z gravity orientations to verify axis labels/signs, zero offsets and sensitivity. Known applied accelerations or a calibrated shaker are needed for high-g scale/bandwidth traceability; a stationary gravity reference does not establish ±320 g accuracy.
6. Write the measured sensor-to-bow rotations as four 3×3 proper orthonormal matrices in `rotations`. The exporter rejects reflections and non-orthonormal matrices. Processing is `(raw_counts * 0.010417 − offsets_g) @ rotation.T`; the orientation applies after local-axis offset correction.
7. Export/analyze with `--calibration calibration.json`. Retain the calibration file with its source shot ID, fixture orientation, date and sensor identities. Recheck the stationary mean after each configuration/mount change and after a test series.

New BVR version 5 time axes retain original ESP32 data-ready interrupt timestamps, with independent sample edges on the same clock. BVR version 3 and 4 time axes use FIFO hardware timestamps and bracketed sensor-clock calibration against the shared ESP32 timer. Version 1 and 2 recordings retain software FIFO-drain timing. Fitted rates, oscillator trim predictions and timing diagnostics are exported; the browser shows the estimated clock-mapping uncertainty. These do not establish synchronous sample edges or characterize analog/filter delay between IMUs. See [synchronization.md](synchronization.md) for the shared start, clock mapping and common-impact acceptance procedure. External TTL/CMOS sync requires a confirmed connector/pin/protection design before firmware can use it.

Analysis removes the mean before XYZ FFT and the RMS vibration envelope. Resultant and reported peak/RMS resultant retain gravity unless the provided offset/orientation calibration removes it. FFT uses the post-trigger portion when sufficient samples exist; a reference with no post-trigger interval uses the whole recording.
